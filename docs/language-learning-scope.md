# 语言学习定位与设计原则

更新日期：2026-11-03

本文明确产品方向、当前能力边界与后续设计原则，不代表多语言适配已经完成，也不确定具体语种的交付顺序。

## 产品定位

Lingo Mate 是一个桌面端通用语言学习助手，面向不同母语的学习者，帮助用户理解、积累、练习和使用自己选择的目标语言。产品设计面向各语言学习场景，具体语言和功能在完成适配、验证后逐步开放。

核心体验是“遇到语言材料 → 理解词汇与表达 → 保存个人资料 → 在语境中练习 → 获得反馈 → 后续复习”。这条学习路径适用于不同语言，具体的语言规则和练习形式需要按目标语言设计。

## 当前版本的范围

当前实现仍以英语为目标学习语言。以下限制应在用户文档中如实保留：

| 范围                     | 当前实现与依据                                                                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 界面与目标语言配置       | 界面支持简体中文和英语；目标语言仅允许 `en`，见 [`preferences.ts`](../src/shared/preferences.ts)                                                               |
| 对话与概念讲解           | Prompt 已区分讲解语言与目标语言，但生产配置仍仅开放英语目标，见 [`conversation/prompts.py`](../agent-engine/src/lingo_agent/workflows/conversation/prompts.py) |
| 词汇、短语、近义词与探索 | 多个 Prompt 明确要求英语词项和例句，见 [`workflows/`](../agent-engine/src/lingo_agent/workflows/)；领域类型也存在 `wordLanguage: 'en'` 约束                    |
| 练习与资料流转           | 使用当前英语资料与校验，不能仅通过新增设置选项就声明支持其他语言                                                                                               |
| 本地朗读与 `/tts`        | 输入及音频协议限定 `language: 'en'`，见 [`speech.ts`](../src/shared/speech.ts)；验证范围见[语音运行时说明](speech-runtime.md)                                  |

普通模型能够回答其他语言的问题，不等于词条收录、练习、查重、导入导出与语音均已支持该语言。英语示例和现有语音测试报告用于描述已实现、已验证的行为。

## 后续能力的设计原则

### 明确语言角色

- **界面语言**：菜单、按钮、通知和无障碍标签使用的语言。
- **母语或熟悉语言**：用于理解学习者背景与跨语言比较，可由用户说明。
- **讲解／反馈语言**：解释、提示、点评使用的语言。
- **目标学习语言**：所学词汇、表达、例句与练习输出使用的语言。

当前讲解通常跟随界面语言。未来是否提供独立设置需另行设计；语言角色应在任务上下文和实际 Prompt 中明确表达。切换界面语言不应改变学习目标；不同角色可以使用相同语言，例如用目标语言讲解目标语言。

### 按语言处理资料与练习

- 词汇、短语、例句、练习表现和未来长期记忆保留目标语言归属；查重、检索和复习应使用相应语言上下文。
- 根据语言处理文字系统、分词、词形变化、大小写和书写方向，不统一假设词语由空格分隔或只包含拉丁字母。
- 发音标注按需要使用 IPA、拼音、假名或其他适合该语言的方式，不将英语音标与词形规则作为统一模板。
- 练习和点评适配相应语法、表达习惯与学习阶段，不机械复用英语练习规则。
- 语音能力按语言及音色单独声明支持范围；文字学习可用不代表朗读也可用。

### 保持现有架构边界

Agent 的语言策略、Prompt 与工作流继续由 Python 持有。TypeScript 宿主负责语言相关领域校验、模型传输、资料归属、持久化和语音能力；Renderer 展示受支持选项与安全结果。具体边界遵循 [AGENTS.md](../AGENTS.md)。

## 新增目标语言前需要完成的工作

1. 确定该语言首批开放的功能，以及界面、讲解与目标语言的组合。
2. 适配共享类型、输入校验和跨语言协议，并让 Python Prompt 显式使用语言上下文。
3. 检查学习资料、查重、探索历史、导入导出和练习记录的语言归属，设计已有英语数据的兼容方式。
4. 适配词汇、表达、练习与反馈规则，覆盖该语言特有的文字、词形和语法行为。
5. 分别验证文字学习与语音能力，完成后同步更新设置选项、翻译资源及用户文档中的支持范围。

上述工作尚未实施。实现时应按项目约定使用可控模型替身和临时数据验证；对真实用户数据库执行迁移或数据变更、执行 E2E 测试前，仍须取得用户明确许可。
