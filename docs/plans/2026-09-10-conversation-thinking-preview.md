# Conversation 等待期间显示思考过程

- 日期：2026-09-10
- 状态：已实施

## 目标与范围

在 conversation 等待 LLM 最终回复期间，实时展示模型接口提供的思考文本或思考摘要。思考内容在任何窗口宽度下最多显示三行，与最终回复正文分离。

本次只编写计划。实施范围覆盖 conversation 的普通对话、重试及复用对话流的回复；技能分析阶段若目前没有思考流，继续显示已有阶段状态，不额外改造非流式分析接口。后台生成会话标题不展示思考内容。

## 当前代码基线

- `src/core/llm/language-model.ts`：`streamReply` 当前返回 `AsyncIterable<string>`，仅表达正文增量。
- `src/core/llm/remote-language-model.ts`：当前只解析 `delta.content`，并校验正常结束和非空正文。
- `src/core/conversation/conversation-module.ts`：消费模型流并发送对话事件，需要区分思考与正文，避免思考写入最终消息。
- `src/shared/conversation.ts`：已有 `started`、`chunk`、`skillPhase` 及完成、失败、取消事件，可沿用现有事件通道扩展协议。
- `src/renderer/src/conversation/conversation-state.ts` 与 `ConversationPanel.tsx`：已有流式消息状态和正文展示，尚无独立思考展示区域。

## 页面与交互

1. 请求开始后，在当前 assistant 消息正文上方显示“正在思考…”占位；收到非空思考增量后显示实际内容。模型不提供思考文本时保留占位，不编造思考过程。
2. 思考内容使用弱于正文的视觉样式和纯文本渲染，保留必要换行，长单词或连续字符允许折行。
3. **三行指实际排版后的视觉行数，而不是按换行符计数。** 内容不足三行时按实际高度展示，超过三行时显示最新内容，自动跟随末尾；容器最大高度为三倍行高并裁剪溢出，不提供展开全文入口。占位同样受高度限制。
4. 第一段正文到达时移除无内容的占位；已有思考预览保留至请求完成，正文按现有逻辑流式显示。正文不受三行限制。
5. 完成后移除思考区域，只保留最终回复；失败、取消时清除思考临时状态，沿用已有错误、取消与重试交互。
6. 重试使用新请求的思考状态；会话切换遵循现有请求隔离，旧请求或已结束请求的迟到事件不得污染当前视图。
7. 思考展示不抢焦点，不逐 token 触发读屏播报；状态提示使用可国际化的无障碍标签。

## 实施步骤

### 1. 模型流区分思考与正文

- 将模型流升级为可判别事件，例如 `{ type: 'text' | 'reasoning', delta: string }`，同步调整 Remote、Configured、Local 实现和全部调用方。
- 在提供方适配边界校验并归一化已确认支持的思考文本或摘要字段；实施时核对项目实际使用的提供方协议，不假定所有模型都支持同一字段。不将签名、加密数据或工具参数作为思考展示。
- 无思考字段的模型保持正常工作；同一分片包含思考和正文时分别处理。保留超时、取消、尾部用量处理及正常结束校验，仅有思考而无有效最终正文不能视为成功。
- 标题生成等纯正文消费者只消费 `text` 事件。保持 Prompt 对输出语言的显式声明；若增加可控的思考摘要指令，明确摘要使用用户界面语言，学习内容继续按任务指定语言输出。

### 2. Core、Shared 与进程桥接

- 在对话事件 schema 中新增 `reasoningChunk`，携带 `requestId`、`sessionId`、`messageId` 与字符串 `delta`，通过现有对话事件通道转发。
- Core 将思考增量与正文增量分别发送；只有正文进入最终消息、会话历史和后续模型上下文，思考内容仅作为本次请求的临时展示数据，不记录到日志。
- 复用 Main 的来源校验和事件转发、Preload 的窄接口及 schema 校验；核查类型传递链。若桥接声明发生变化，同步更新 `src/preload/index.ts` 和 `src/preload/index.d.ts`。
- 不新增数据库字段或思考持久化。若实施范围变化涉及数据库迁移或真实持久化数据变更，按项目约定先询问用户。

### 3. Renderer 状态与三行预览

- 在当前 assistant 草稿中维护独立的临时思考状态，按请求、会话和消息 ID 校验增量归属，沿用已完成请求去重和迟到事件处理。
- 为预览设置有界尾部缓冲（首版最多 4,000 个 Unicode 码点），避免长时间生成无限累积；缓冲限制与三行视觉限制分别实现。
- 在 conversation 目录内新增思考预览组件，使用明确行高、最大高度和溢出裁剪；在内容、窗口宽度或字号变化后保持末尾可见，确保任何状态都不出现第四行。
- 更新中英文 `conversation.json` 中的占位及无障碍文案，通过统一 i18n key 获取静态文本。

## 验证与验收

- 模型适配测试：思考后正文、同分片思考和正文、无思考字段、空思考、只有思考无正文、异常结束、取消，以及标题消费者忽略思考。
- Core / Shared 测试：事件校验和归属、正文与思考分离、思考不进入持久化消息及后续上下文、完成后停止转发。
- Renderer 状态与组件测试：占位、增量更新、正文开始、完成、失败、取消、重试、切换会话、迟到事件、缓冲上限和中英文文案。
- 使用真实浏览器布局测试验证三行约束：覆盖中文、英文、显式换行、连续长字符串、窄窗口及字号变化；断言内容可见高度不超过三倍行高，最新内容可见，最终回复不被裁剪。不能仅靠 jsdom 或 CSS 类名断言证明三行限制。
- 测试放入模块内 `__tests__/`；跨模块与端到端测试分别放入 `tests/integration/`、`tests/e2e/`，使用假模型与临时数据目录。
