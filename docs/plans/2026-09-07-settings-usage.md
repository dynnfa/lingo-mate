# Settings Usage：Token 用量图表计划

- 日期：2026-09-07
- 状态：待实施
- 目标：在设置页左侧新增 Usage 菜单，右侧通过图表展示日、周维度的 token 用量，并支持查看每日用量。
- 本次交付为实施计划。

## 当前实现与前置依赖

- `src/renderer/src/settings/SettingsPage.tsx` 通过 `SETTINGS_SECTIONS` 注册左侧菜单，现有语言、模型两个区块；右侧通过 `hidden` 切换详情，模型草稿在菜单切换时保留。
- 当前源码尚未实现 token 用量账本。先完成 [LLM 请求 Token 用量记录计划](./2026-09-07-llm-token-usage.md)，再接入真实统计数据；该计划中“不增加统计页面”的首版范围由本计划后续扩展。
- 复用该计划中的 `llm_request_usage`、请求起始时间及 input/output/total 字段，不从会话正文推算用量，不创建第二份账本。
- 当前依赖没有图表库。首版使用 React + SVG 实现简单柱状图，沿用现有 CSS 样式，不为单一图表引入额外运行时依赖。

## 页面与交互

### 菜单和详情区

1. 在模型菜单下方追加 `usage` 区块，英文显示 `Usage`，简体中文显示“用量”，通过统一翻译 key 获取。
2. 点击后，右侧显示标题、统计说明、今日／本周摘要卡、日／周切换控件和用量图表。
3. 沿用设置页布局、选中状态、返回按钮和 Escape 行为；从模型区块切到 Usage 仍取消在途连接测试，保留未保存的模型草稿。
4. Usage 首次激活时读取数据；再次进入、切换统计范围或点击刷新时重新读取。保留本次设置页会话内的维度与选中周，首版不增加持久化偏好。

### 日、周维度

以下为首版默认产品口径，实施时按此落地：

| 项目 | 展示与行为 |
| --- | --- |
| 今日摘要 | 本地当天截至刷新时的总 token，附输入／输出 token |
| 本周摘要 | 本地周一至今的总 token，附输入／输出 token |
| 日维度（默认） | 最近 30 个自然日，包含今天；横轴为日期，每根柱代表当天总 token |
| 周维度 | 最近 8 个自然周，包含本周；横轴为周起止日期，每根柱代表该周总 token |
| 每日明细 | 周维度下默认选中本周；点击某周柱，在下方展示该周周一至周日的每日用量柱状图 |
| 数值详情 | 悬停或键盘聚焦显示完整日期／周范围、总 token、输入 token、输出 token 及数据完整性提示 |

- 图表纵轴从 0 开始，标注 token；轴标签可用本地化紧凑格式，详情展示完整数字。总量使用独立柱，输入／输出在详情中展示，避免在提供方字段不一致时制造错误的堆叠关系。
- 今日、本周均明确标注“截至当前”；当前周尚未发生的日期显示为“未到日期”，不画成已完成的零用量日。
- 无调用的已发生日期补齐为 0，保持时间轴连续；有调用但用量未知的日期使用独立标记，不能表现成确认的 0。
- 支持键盘访问数据点和周选择；提供可展开的数据表，展示与图表相同的日期、数量和完整性信息，不只依赖颜色或鼠标 tooltip 传达数值。
- 首版覆盖全部模型和调用入口，不增加模型筛选、费用估算、导出、自定义日期范围或小时维度。

## 统计口径

1. 按账本的 `started_at` 归属日期，跨午夜请求仍归入开始当天；周从周一开始。使用系统本地时区，与界面语言分别处理。
2. 数据库存储 UTC 毫秒时间戳，Core 根据时区计算自然日／周的 `[start, end)` 边界，再交给仓储汇总。必须按日历推进，不能假设每个本地日固定为 24 小时；查询不包含快照时刻之后的记录。
3. 同一响应内所有视图使用同一个 `asOf` 和时区，汇总读取保持一致快照，避免在途请求收尾造成卡片与图表互相矛盾。系统时区改变后，下次查询按新时区重新归属历史记录。
4. 统计普通对话、词汇分析、连接测试等所有真实调用；失败、取消、中断请求只要存在可信用量也计入。请求状态不作为“是否消耗 token”的判断依据。
5. 分别累计有效的 input/output/total；total 使用账本中已记录的提供方值或已标记的派生值，不在展示层再次推导或补算。`usage_status = invalid` 的记录不进入 token 合计，单独计入异常记录数。
6. `NULL` 表示未知，0 表示提供方明确返回的零或该时间桶无调用。若部分请求未知，显示“已知用量”和未完整记录请求数；若某指标所有调用均未知，则该指标显示“未知”，不能单独显示 0。`partial` 中有效字段可进入对应已知合计，并保留该指标未知记录数。
7. 运行中的记录计入请求数并标注统计可能变化；首版采用进入／切换／手动刷新获取快照，不增加常驻轮询或用量推送协议。
8. 每周总量必须等于该周每日已知总量之和；今日、本周摘要与相应图表遵循相同的有效性规则。
9. 页面说明“仅统计启用记录后的本机调用；提供方可能未返回完整用量”。历史没有记录不能解释为用户从未使用，账本无法观测的写入失败也不能承诺精确统计。

### 查询协议

- 首版一次 `getOverview` 返回今日／本周摘要、最近 30 日桶、最近 8 周桶及这些周对应的日桶；Core 以覆盖两类窗口的有限区间查询，不扫描无限历史、不传递所有原始记录。Renderer 切换维度可先展示已有快照，再刷新。
- 请求只允许预定义窗口，首版可使用空对象；时区和当前时间由 Main/Core 提供，不接受 Renderer 传 SQL、任意文件路径或无限时间范围。
- 响应包含 `asOf`、`timeZone`、窗口边界、摘要、日桶和周桶。桶包含稳定 key、UTC 起止时间、本地日期标签所需数据、三类已知 token 合计、对应未知计数、请求数、异常记录数及是否尚未发生。
- token 合计需进行安全整数检查，聚合溢出返回安全统计错误，不悄悄舍入。周桶按同一份日桶聚合，避免日／周规则漂移。
- API 只返回聚合元数据，不返回密钥、Prompt、对话内容、工具参数或提供方原始错误。Renderer 只调用 `window.api`，不导入 Core、数据库、Node.js 或 Electron。

### 状态与国际化

- 首次加载显示骨架；已加载后刷新保留快照并显示刷新状态及更新时间，失败时明确标记数据未更新。
- 查询失败提供重试；空账本显示空状态和范围时间轴；记录存在但全未知时显示“用量未知”，与空账本区分。
- Hook 用请求序号或清理标记忽略过期响应，防止快速切换、重复刷新或页面卸载后覆盖新状态。
- 菜单、标题、维度按钮、图例、tooltip、表格、加载／错误／空状态、完整性说明及无障碍标签均使用 i18n key。日期和数字按当前界面语言格式化，语言切换不能改变统计边界。
