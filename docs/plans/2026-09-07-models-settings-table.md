# 模型配置页面表格化重构计划

- 日期：2026-09-07
- 状态：待实施；本次只生成计划，不修改业务代码。
- 关联计划：[Settings Models 配置计划](./2026-09-05-settings-models.md)

## 目标与范围

将 Settings → Models 从单套配置表单重构为已配置 LLM 的管理表格。API Key 脱敏显示，最右侧固定为操作列，提供「删除」「编辑」「测试连通」。

本计划按可保存多条 LLM 配置设计，因此同时包含配置集合、稳定记录 ID、旧数据迁移和当前使用模型的选择规则。保留现有新增配置能力，新增与编辑复用同一表单。继续使用现有 OpenAI-compatible 协议，不扩展供应商原生协议、自动模型发现、批量操作或按学习任务分配模型。

## 页面结构

```text
模型                                      [新增模型]
当前使用模型：[选择已保存配置 ▾]

┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────────────────┐
│ Model ID │ Base URL │ 协议     │ API Key  │ 测试状态 │ 操作                 │
├──────────┼──────────┼──────────┼──────────┼──────────┼──────────────────────┤
│ model-a  │ https…   │ OpenAI…  │ •••••••• │ 未测试   │ 删除 编辑 测试连通   │
│ model-b  │ http…    │ OpenAI…  │ 未配置   │ 测试成功 │ 删除 编辑 测试连通   │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────────────────┘

新增／编辑时，在表格下方展开复用表单：
Base URL / Model ID / API Key / 移除已保存密钥
[测试草稿] [保存] [取消]
```

- 表格只展示已成功保存的配置，每条配置一行，以内部 `id` 为 React key；新增草稿不提前插入表格。
- 当前模型选择器用 Model ID 与 Base URL 共同标识配置；它位于表格上方，操作列保持用户要求的三个动作。
- 空列表展示国际化空状态和新增入口。加载中与读取失败分别处理，读取失败提供重试，不能被视为空列表。
- 模型区块单独放宽现有 `.settings-section-body` 的 480px 限制，语言设置区块保持原宽度。
- 使用原生 `table`、表头和明确的按钮标签。长 URL 截断并支持查看完整非敏感内容；窄窗口允许表格容器横向滚动，最右侧操作列使用 sticky 保持可达，不能让整个设置页横向溢出。
- 测试提示继续说明会发送请求、可能产生费用。所有表头、按钮、状态、错误、确认文案和无障碍名称进入 `zh-CN`、`en` 翻译资源。

## API Key 脱敏规则

1. 已保存且可用的密钥统一显示固定长度掩码 `••••••••`，不显示真实前缀、后缀或长度；无需增加含密钥片段的 DTO。
2. 未配置密钥显示「未配置」，允许使用无需密钥的本地服务。
3. 已存密钥无法解密时显示「密钥不可用，请重新配置」，不伪装为未配置。
4. 列表、编辑表单、DOM 属性、tooltip、错误及日志均不得包含从存储读取的真实密钥。Main/Core 只返回安全摘要；Renderer 根据摘要显示掩码。
5. 编辑时密码框始终为空。保留 `keep`／`replace`／`remove` 凭据意图：留空保留该条记录的密钥，新输入替换，明确勾选移除才删除。新增时空输入表示无密钥，不继承其他记录的凭据。
6. 掩码仅用于展示，不进入表单值或提交载荷。用户本次输入的新密钥仅作为临时草稿单向提交，保存成功、放弃编辑或退出设置后清空。
7. 编辑 Base URL 跨 origin 时继续要求替换或移除旧密钥；既有凭据隔离与加密存储规则不变。

## 操作与状态规则

### 新增与编辑

- 新增打开空表单；编辑按配置 ID 加载该行非敏感字段，复用现有字段校验和凭据操作。
- 同一时间只编辑一条配置。有未保存修改时，新建、切换编辑目标、取消表单或退出设置先确认是否放弃；切换语言设置菜单仍保留草稿。
- 无修改时禁用保存；提交期间防止重复保存。保存成功后以 Main 返回的集合刷新表格并关闭表单，失败保留草稿和原记录。
- 编辑保持记录 ID 和当前模型选择不变；保存后清除此行旧测试结果。未保存的编辑不会改变表格或运行时配置。
- 保留「测试草稿」能力并明确其名称：它验证当前输入，结果仅属于编辑表单，不覆盖已保存配置的行测试结果，不自动保存。
- Escape 优先关闭当前确认层或处理编辑表单，再执行退出设置，避免一次按键同时触发多个动作；关闭表单后焦点回到来源按钮。

### 删除

- 点击删除后以 Model ID 与 Base URL 标明目标，确认后仅删除对应记录及凭据，取消不修改数据。
- 删除当前使用模型时，确认文案明确说明删除后需要重新选择模型；删除成功把 `activeConfigId` 设为 `null`，不自动切换到其他提供方。
- 删除非当前模型不影响当前模型。最后一条删除后进入空状态。
- 目标存在未保存编辑时，删除确认同时明确草稿将被丢弃；只在删除成功后清理对应草稿和测试结果，失败保持原行并显示可重试错误。
- 操作期间显示删除中并禁用重复提交；成功后焦点移至下一行操作按钮，空列表时移至新增入口。

### 测试连通

- 行操作只提交 `{ configId, requestId }`，由 Main 调用 Core 读取该条已保存配置和密钥。即使表单有草稿，行测试仍针对已保存版本。
- 复用 `ModelConnectionTester`、15 秒截止和现有错误分类。最小测试请求不包含会话历史或学习记忆，并保留 Prompt 显式指定英文输出的指令。
- 行状态包括未测试、测试中、成功、失败和已取消；使用可访问状态提示，失败显示国际化原因，允许再次测试。
- 保持每窗口最多一个测试（行测试和草稿测试共享限额）。测试时禁用其他测试入口，以及测试目标的编辑、保存和删除；其他行可继续浏览和管理。
- 结果按配置 ID 与 requestId 关联。取消后立即使本地请求标识失效，迟到回调不能覆盖新测试状态或已删除的行；卸载后忽略回调。
- 切离 Models、退出设置或窗口销毁时中止测试。结果仅保存在当前设置页会话中，重新进入显示未测试；不将成功结果当作永久可用保证。

## 配置集合与运行时选择

持久化升级为版本 2，结构示意如下（`credential` 为加密内容，绝不属于 Renderer DTO）：

```ts
interface StoredModelsConfigV2 {
  schemaVersion: 2
  activeConfigId: string | null
  configs: Array<{
    id: string
    protocol: ModelProtocol
    baseUrl: string
    modelId: string
    credential?: string
  }>
}
```

- `id` 由 Main 注入 Core 的 ID 工厂生成并持久化，不使用 Model ID、数组下标或 URL 作为主键。允许同一 Model ID 对应不同地址或凭据的独立记录。
- 第一条配置新增成功时自动设为当前模型；后续新增不改变选择。非空列表但当前模型为空时，要求用户通过选择器显式选定。
- 当前模型选择与集合一起原子保存。保存失败不发布新的运行时状态；`activeConfigId` 必须为空或指向存在的记录，损坏数据按读取失败处理。
- `resolveSnapshot()` 继续作为对话及其他现有调用方的入口，只解析当前模型；行测试使用单独的按 ID 解析入口，不改变当前选择。
- 当前模型为空时沿用未配置错误流程，提示用户到设置选择模型；不回退到模拟模型。修改、删除或切换模型只影响后续请求，在途请求继续使用开始时的快照。
- 版本 1 首次读取时迁移为单元素集合并将其设为当前模型，保留原字段及加密密钥，不要求重新输入或重新加密。迁移成功必须原子落盘，确保 ID 跨重启稳定；失败保留原文件并报告错误。版本 2 再次读取不重复迁移；未知版本或损坏内容不覆盖为空集合。

## 跨层契约与实施顺序

1. **Shared 与 Core**：定义列表摘要（`configs`、`activeConfigId`）和逐条记录摘要，保留密钥状态字段；扩展版本 2 校验、迁移、按 ID 新增／更新／删除、当前模型选择及快照解析。补充非法 ID、记录不存在等稳定错误码，禁止更新不存在的记录时隐式新增。
2. **Main 与 Preload**：建议统一为 `listConfigs()`、`createConfig(input)`、`updateConfig({ configId, ...input })`、`deleteConfig({ configId })`、`setActiveConfig({ configId })`、`testSavedConnection({ configId, requestId })`、`testDraftConnection(input)`、`cancelTest({ requestId })`。草稿测试显式区分新增／编辑目标，编辑仅允许使用该 ID 的凭据。集中定义对应 `models:*` channel，全部通过 Zod 校验；保留来源检查、取消归属和安全错误映射。同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 及所有调用方、mock，移除被替代的单配置 API。
3. **Renderer 状态**：重构 `useModelsSettings` 为列表、当前模型、编辑会话、删除目标和测试结果状态；持久化写操作串行，使用返回的完整安全列表刷新，避免并发响应覆盖。列表载荷不含密钥，业务规则仍由 Core 执行。
4. **Renderer 视图**：`ModelsSettings` 负责组合表格与表单；按实际复杂度提取 `ModelsTable.tsx`、`ModelConfigForm.tsx`，避免复制现有字段逻辑。接入设置页退出保护、焦点管理、表格滚动和中英文资源。
5. **验证与文档**：更新原有单配置测试、增加集合与迁移场景，通过下列检查后将本计划状态改为已实施，并在旧计划注明后续由本计划扩展。
