# 已记录词汇导入与导出计划

- 日期：2026-09-16
- 状态：待实施
- 范围：已记录 → 词汇菜单

## 目标

1. 在词汇菜单添加「导入」和「导出 Excel」入口。
2. 导出只支持 Excel（`.xlsx`），导出全部已记录词汇，而非当前已加载的分页。
3. 导入提供两种方式：「Excel 直接导入」和「AI 辅助导入」。
4. 直接导入先提供 Excel 模板下载，用户按指定字段填写完整内容，校验后写入 SQLite，不调用 LLM。
5. AI 辅助导入提供 textarea，一行一个英文 word；LLM 逐行生成学习内容，校验后写入 SQLite。

本次仅制定方案，不执行数据库迁移或修改用户持久化数据。实施时如涉及数据库迁移或持久化数据变更，先按项目约定询问用户，再执行相应操作。

## 现有能力与复用边界

- `src/renderer/src/recorded/vocabulary/VocabularyDetail.tsx` 已提供词汇分页列表和删除交互。
- `src/shared/vocabulary.ts` 定义词条、分页、批处理结果及管理 API；当前管理 API 只有 list/delete。
- `src/core/learning/vocabulary/vocabulary-insert.ts` 已提供内容校验、固定参数化 INSERT 和系统字段组装。
- `src/core/llm/llm-vocabulary-analyzer.ts` 已支持单词分析，返回音标、释义、概念及 1–3 条例句。
- `src/database/sqlite-vocabulary-repository.ts` 已提供事务写入及词项归一化查重。

复用内容分析和存储能力；导入作为独立词汇管理流程，不创建聊天消息，也不依赖 conversation skill execution。现有会话批处理协议限制最多 20 项，新增导入协议应独立定义，不能直接套用其 inputIndex 和批量上限。

## 页面与交互

词汇菜单标题区增加「导入」和「导出 Excel」。空词库也能进入导入和下载模板。

### Excel 直接导入

1. 打开导入弹窗，选择「Excel 直接导入」。
2. 点击「下载 Excel 模板」，通过系统保存对话框保存 `.xlsx`。
3. 按模板填写后点击「选择 Excel 文件」，通过系统文件对话框选择 `.xlsx`。
4. 解析并展示总行数、有效行数、重复行及逐行错误；错误包含 Excel 行号、字段和原因。此阶段不写库。
5. 校验全部通过后启用「确认导入」，一次短事务提交全部有效且未存在的记录。存在非法行时先修正文件再导入，避免静默丢失内容。
6. 展示新增、已存在、文件内重复数量；刷新词汇列表。数据库提交失败时整批回滚。

### AI 辅助导入

1. 选择「AI 辅助导入」，显示 textarea，提示「每行输入一个英文单词」。
2. 按换行拆分，兼容 LF/CRLF；去除行首尾空白、忽略空行，保留原始行号。不按逗号或空格再次拆分，不让模型自动扩展成多个词。
3. 开始前校验输入上限及模型配置，展示有效词数；先做批内和词库查重，重复词不重复请求模型。
4. 点击「开始导入」后逐词调用现有 analyzer，展示已处理/总数及成功、重复、失败状态。首版顺序调用，避免无界并发。
5. 全部分析结束后，将成功内容放入一次短事务保存；单词无法识别、超时或返回非法结构不阻止其他词分析。事务内再次查重，避免分析期间新增的同词重复入库。
6. 展示逐行结果和统计，允许仅重试失败行；成功提交后刷新词汇列表。

任务支持完成、部分成功、失败和取消。分析阶段取消时中断当前模型请求，不再发起后续请求，本次尚未提交的内容全部丢弃。进入同步提交阶段后不能取消，界面等待明确提交结果，不能显示已取消但实际入库。窗口销毁时取消未提交任务；切换菜单后能恢复当前任务状态。同一窗口一次只运行一个导入任务，重复点击不创建重复任务。

### 导出 Excel

- 点击后通过系统保存对话框选择路径，输出全部词汇的 `.xlsx`；取消选择属于正常取消。
- 使用与直接导入相同的业务列，按 `created_at DESC, id DESC` 排序；稳定读取导出数据快照，不能只导出 Renderer 当前页。
- 空词库输出只有表头的工作表，可作为空模板使用。
- 设置可读列宽、表头样式和长文本换行；用户内容作为字符串单元格写入，不能转换成公式。
- 历史词条中允许为 NULL 的字段导出为空白，不伪造内容。重新直接导入时仍执行完整内容校验，提示补齐缺失字段；导出不承担数据库备份与恢复职责。

## Excel 模板与字段映射

工作簿使用固定数据 sheet `vocabulary`，第一行为稳定英文协议列名；另设说明 sheet，按当前界面语言说明字段、必填规则和填写示例。示例不放入数据区，避免被误导入。导出文件沿用同一结构。

| Excel 列名           | 必填 | SQLite 映射            | 规则                                                                 |
| -------------------- | ---- | ---------------------- | -------------------------------------------------------------------- |
| `term`               | 是   | `term`                 | 非空英文词项，最长 4000 字符，保留用户大小写；去重使用已有归一化规则 |
| `phonetic`           | 是   | `phonetic`             | 最长 200 字符，复用现有 IPA 格式校验                                 |
| `meaning`            | 是   | `meaning`              | 非空释义，最长 2000 字符                                             |
| `concept`            | 是   | `concept`              | 非空概念说明，最长 2000 字符                                         |
| `example_sentence_1` | 是   | `example_sentences[0]` | 非空例句，最长 500 字符                                              |
| `example_sentence_2` | 否   | `example_sentences[1]` | 最长 500 字符                                                        |
| `example_sentence_3` | 否   | `example_sentences[2]` | 最长 500 字符                                                        |

- 例句按列顺序收集非空值，最终为 1–3 条字符串数组，应用执行 `JSON.stringify` 后存入 `example_sentences`。
- 列顺序允许变化，按列名映射；所有表头必须存在，重复、缺失或未知表头明确报错。全空行忽略，有内容的行逐字段校验。
- 不执行 Excel 公式，不使用公式缓存结果作为导入内容；公式、错误值及不符合文本字段要求的单元格返回行级错误。
- `id` 和 `created_at` 由应用生成，不接受文件指定；直接导入使用 `model_id = manual-import`、`prompt_version = vocabulary-excel-v1` 作为来源标记，AI 导入保留真实模型 ID 和 Prompt 版本。
- 导出不包含内部 ID、模型配置或其他系统字段。完整内容的导出文件可直接用于导入；已存在的词跳过且不覆盖原记录。
- 首版限制建议：Excel 文件最多 5 MiB、1000 条数据行；AI 每次最多 100 个非空行，总文本最多 10000 字符。限制集中配置，在界面提示并在 Main/Core 校验；解析器另设解压后大小及单元格数量上限。

## 分层实现

### Shared 与 Preload

- 在 `src/shared/` 定义专属导入导出 Zod 协议、channel、任务状态、行结果和安全错误码，数据必须可序列化。
- 在 `window.api.vocabulary` 增加业务接口：下载模板、预检 Excel、确认 Excel 导入、启动 AI 导入、读取任务状态、取消导入及导出 Excel。
- Excel 预检结果返回短期有效的 opaque importId；Main 保存已校验内容，并绑定请求窗口，确认导入只接受该 ID，不信任 Renderer 回传的行数据或文件路径。重复确认返回相同结果，不重复提交；过期或窗口销毁时释放内容。
- AI 使用 requestId 关联任务，进度通过受控订阅推送，提供取消订阅，并支持查询最终状态，避免事件丢失导致 UI 永久等待。
- 同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 和相关测试 mock；不暴露任意 channel、文件系统或数据库能力。

### Main

- 负责系统文件选择/保存对话框、Excel 编解码适配器及文件读写；实施时选择支持显式字符串单元格与受限解析的 `.xlsx` 库，依赖仅用于有权限的进程。
- IPC 保留来源、输入、输出校验；若统一 IPC guard 已落地则使用，否则沿用现有可信主 frame 检查，不默认该计划已实施。
- 管理任务所有权、资源清理、模型配置和语言设置，将纯数据交给 Core。所有确认、查询和取消都检查任务所属窗口。
- 文件对话框标题和错误提示纳入国际化。跨进程错误只携带安全错误码、行号和字段，不返回 SQL、路径、堆栈或密钥。

### Core

- 在 `src/core/learning/vocabulary/` 增加导入服务，负责字段校验、逐行解析、去重、任务状态和结果汇总；Excel 文件格式细节留在适配器中。
- 直接导入使用经过验证的完整内容构造既有固定 INSERT 命令，不调用模型。
- AI 导入通过依赖注入复用 `VocabularyAnalyzer`，每次请求只传一个 term；词项始终视为不可信数据，不执行其中的指令。
- 每次 Prompt 显式指定：meaning/concept 使用当前用户设置的解释语言，例句使用英语，phonetic 为 IPA，协议字段名和枚举保持稳定。
- LLM 只提供结构化内容，SQL 与系统元数据由应用生成，写库前通过 schema 校验；不接受模型生成的 SQL。

### Database

- 优先复用现有词表、`buildVocabularyInsertCommand` 和 `saveBatch`，不预设 schema 迁移，不写入会话执行记录。
- 复用 `normalizeLookupKey`，批内重复保留首条，数据库已有记录跳过，不更新旧记录。结果区分 saved、existing、duplicate、failed。
- 导出提供专用完整读取能力，保持一致数据视图；文件生成放在读取结束之后，不在数据库事务中执行文件 I/O 或 LLM 请求。
- 为手动来源标记增加兼容性验证，确保现有读取和其他消费方不会将其错误当作必须存在的模型配置 ID。

### Renderer 与国际化

- 导入弹窗、两种导入面板、任务 hook 和结果组件收拢于 `src/renderer/src/recorded/vocabulary/`，对应测试放入其 `__tests__/`。
- 所有按钮、提示、占位符、进度、错误、模板说明及无障碍标签通过 i18n 获取，同步维护 zh-CN/en，动态数量使用插值和复数规则。
- 弹窗支持键盘操作、焦点管理及进度播报。完成后重新加载列表，避免仅在前端追加而破坏分页排序。

- 单元测试：模板字段映射、列重排、缺失/重复表头、空行、超长字段、例句序列化、公式拒绝、容量限制与来源标记。

- IPC 测试：非可信来源、非法输入、其他窗口任务访问、失效 importId、窗口销毁清理、安全错误与进度协议。

- 手动验收：两种导入都能在已记录词汇列表看到结果；导出只有 Excel 一种选项；模板在 Excel 中可填写，结果文件可正常打开；zh-CN/en 文案完整。
