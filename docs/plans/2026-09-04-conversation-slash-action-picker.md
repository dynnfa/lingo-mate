# Conversation `/` 行动选择器计划

## 状态与目标

- 状态：Implemented（2026-09-05 实施完成）。选择器交互、过滤、无障碍、国际化已落地；单元测试、组件测试、i18n 资源测试与 Electron e2e（定位、键盘、点击关闭）全部通过；实机中文输入法抽查仍建议人工复核。
- 目标：当 conversation 输入框的第一个字符为半角 `/` 时，在输入框上方弹出行动选择窗口，让用户选择想要做的事情。
- 实施范围：优先限定在 Renderer 的输入交互、弹层、样式、国际化和测试；具体行动若涉及 Agent 能力，再单独确定 Core 与跨进程协议的变更。
- 关联计划：[ConversationPanel 拆分](./2026-09-04-conversation-panel-extraction.md)。

## 现状

`src/renderer/src/conversation/ConversationPanel.tsx` 已持有本地 `draft`，通过单行 `<input>` 接收输入，并由表单提交调用 `onSend(draft)`。输入上限为 4000 字符；`composerLocked` 控制是否允许输入和发送，生成期间显示取消按钮。

当前没有 slash command、行动目录或弹层状态。未发送草稿在切换、新建会话及切换界面语言时保留。新交互应沿用这些行为，不改变普通消息的发送、取消和重试流程。

## 交互约定

以下为建议的首版规则，具体行动内容与选中结果见文末待确认项。

### 触发与过滤

- 以原始 `draft.startsWith('/')` 判断，不先 `trim`。输入 `/` 展示全部可用行动；在首位粘贴 `/...` 同样触发。
- `hello /`、` /` 和全角 `／` 不触发；不是只要光标前出现 `/` 就打开。
- 仅当输入框聚焦且未锁定时显示窗口。中文等输入法组合输入期间不刷新候选，不拦截确认键；组合输入结束后再判断。
- `/` 后的文本作为查询词，按稳定命令名和当前界面的本地化名称进行不区分大小写的子串过滤；顺序沿用行动目录，不增加模糊搜索依赖。
- 查询为空时展示全部行动；无匹配时保留窗口并展示国际化空状态，不伪造候选。
- 首次打开默认高亮第一项；查询变化后重新高亮第一项，无结果时没有高亮项。

### 展示与定位

- 窗口锚定输入区，在其正上方展开，与输入区保持小间距；不是居中对话框或独立 Electron 窗口。
- 每项展示行动名称、简短说明及稳定命令名（如 `/translate`；仅为交互示例，不代表已确定功能）。
- 使用现有颜色、边框、圆角和阴影变量；浮层覆盖消息区域，不挤压消息列表或改变输入区位置。
- 宽度对齐输入区且不超出面板；高度受可用空间限制，候选过多时内部滚动，高亮项保持可见。
- 首版优先使用输入区定位容器和绝对定位；核对祖先的 overflow、层叠关系和小窗口布局，确有裁切问题再考虑 Portal，不预先引入弹层框架。

### 选择、关闭与发送优先级

- 窗口打开时，`ArrowDown` / `ArrowUp` 移动高亮并循环；`Enter` 选择高亮项，必须阻止本次表单提交，不能同时发送 `/...`。
- 鼠标点击候选与键盘确认使用同一选择入口。处理好 pointer 与 blur 的顺序，避免窗口先关闭导致点击失效。
- `Escape` 关闭窗口并保留草稿；`Tab` 关闭并沿正常焦点顺序离开，不选择候选、不锁住焦点。
- 点击窗口和输入区之外、输入框失焦、删除首位 `/` 或输入被锁定时关闭窗口。关闭操作不清空草稿。
- `Escape` 或外部点击关闭后，同一草稿不会因普通重渲染立刻重开；下一次用户修改符合条件的草稿，或重新聚焦输入框时可以重开。
- 窗口打开时，发送按钮禁用；即使没有匹配项，`Enter` 也不把查询误发为普通消息。表单提交处理必须另有保护，不能只依赖按钮禁用。
- 显式关闭窗口后，允许按既有流程发送以 `/` 开头的普通文本，保留用户输入字面量的能力。
- 选择后关闭窗口并将焦点留在输入框。建议首版选择仅进入所选行动的待输入状态，不立即请求模型；替换哪些文本、如何补充参数以及提交入口，需随行动定义确认后实施。
- 若选择后草稿仍以 `/` 开头，应显式抑制该草稿重新触发窗口，不能在选择动作完成后立即弹回。

### 无障碍与状态保留

- 输入框采用带列表弹层的 combobox 语义，维护 `aria-expanded`、`aria-controls`、`aria-autocomplete="list"` 和有效的 `aria-activedescendant`。
- 候选容器使用 `listbox`，候选使用稳定 ID、`option` 与 `aria-selected`；键盘浏览时实际焦点留在输入框，关闭后清理悬空的活动项引用。
- 输入框原有可访问名称保留；窗口名称、候选名称和说明、无结果提示均通过 i18n 提供。
- 锁定及会话切换可以关闭临时窗口，但不清除草稿；解除锁定不主动抢焦点。
- 界面语言变化时重新翻译并更新过滤结果，保证高亮项有效；不改写用户输入或重建会话。

## 实现设计与职责

### Renderer 内的最小拆分

- `ConversationPanel.tsx`：继续持有草稿，协调触发条件、关闭抑制、键盘事件和选择回调；在现有提交入口增加窗口打开及输入法状态保护。
- 新增 `ConversationActionPicker.tsx`：只负责候选列表、空状态及选择意图，不读取 Controller、不调用 `window.api`，不自行发送消息。
- 新增 `conversation-actions.ts`：保存稳定行动 ID、命令名、名称与说明的翻译 key；提供可单测的触发解析及候选过滤函数。仅存展示元数据，不存 Prompt 或业务执行逻辑。
- `assets/main.css`：新增作用域明确的输入行、弹层和候选样式；现有 `.composer > div` 等结构选择器需检查，避免新增弹层误继承输入行布局。
- `i18n/locales/zh-CN/conversation.json` 与 `i18n/locales/en/conversation.json`：同步增加 `actionPicker` 及各行动的文案 key。

候选结果和是否符合 `/` 前缀由草稿派生；本地状态仅保存必要的焦点、组合输入、关闭抑制及高亮身份，不复制会话状态，不引入全局 Store 或通用命令总线。

### 行动接入边界

选择器只表达稳定行动 ID，不以翻译后的名称作为执行协议。具体行动列表及输入/提交方式确认前，不将演示行动作为已可用功能发布。

如果行动只是现有界面操作，通过明确回调衔接；如果需要新的学习能力或模型调用，业务规则和 Prompt 位于 `src/core`，通过 Main 与窄类型 Preload API 接入，必要时同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 和 Shared 可序列化协议。不得在 Renderer 拼接业务 Prompt、导入 Core 或直接调用 Electron。

所有实际发送给模型的行动指令必须显式指定输出语言；混合语言输出需分别指定解释和例句等字段的语言。该接入属于行动定义后的后续范围，不因增加选择窗口而默认修改数据库或 LLM 链路。

## 测试与验收

### 自动化覆盖

- 触发：`/`、首位粘贴、继续输入查询；非首位 `/`、前导空格、全角 `／` 不触发；删除前缀关闭。
- 过滤：命令名、本地化名称、大小写、空查询、无匹配；过滤后高亮不会越界。
- 选择：上下键、首尾循环、鼠标点击、回车仅选择一次且不调用 `onSend`；无候选回车不发送。
- 关闭：Escape、Tab、外部点击、失焦、锁定；同一草稿重渲染不重开，编辑或重新聚焦可重开；选择后不立即弹回。
- 提交保护：打开窗口时按钮禁用且直接触发表单提交也不发送；关闭后可发送字面 `/...`；输入法确认不误选、不误发。
- 状态与回归：锁定及会话切换不丢草稿，取消/重试行为不变，普通消息仍传原始草稿并在提交后清空。
- 国际化与无障碍：两种语言资源一致，切换语言不丢草稿，ARIA 关联和高亮状态随打开、过滤及关闭正确变化。

## 待确认的产品决策

1. 首版提供哪些行动，以及显示顺序、名称与说明？翻译、润色、口语练习仅可作为讨论例子，并非本需求已确认范围。
2. 每个行动选中后，是填入可编辑模板、进入带参数的输入模式，还是直接执行？本计划暂按"选择不自动发送，用户补充输入后确认"设计，最终需逐项确定。

以上决策不影响先明确选择器的交互边界，但会影响行动状态模型、提交接口与是否需要 Core/IPC 改动；应在实施行动接入前确认。

## 首版行动决策（2026-09-05 实施时确定）

在保持"选择器只表达稳定行动 ID、不发布不可执行功能"的前提下，首版按交互外壳落地：

- 首版目录（顺序即展示顺序）：
  - `translate` / `/translate` — 翻译：把文本翻译成目标语言，并解释关键词汇和用法。
  - `polish` / `/polish` — 润色：改进表达、语法和自然度，保留原意。
  - `practice` / `/practice` — 口语练习：围绕一个话题展开对话，练习口头表达。
- 选中行为：按计划默认设计，选择只把草稿替换为 `/command `（命令名 + 空格）进入待输入状态，不立即请求模型；用户补充内容后按既有发送流程以字面文本提交。因此首版不存在"不可执行的占位行动"——每个行动都产生真实、可发送的命令草稿。
- 后续范围：为各命令接入真实的 Core 业务能力（Prompt、输出语言约定、跨进程协议）时，再更新 `src/preload/index.ts`、`src/preload/index.d.ts` 与 Shared 可序列化协议；行动目录与选择协议届时以稳定 ID 扩展。

## 实施结果记录（2026-09-05）

- 交付物：`conversation-actions.ts`（目录 + 解析/过滤纯函数）、`ConversationActionPicker.tsx`（候选弹层）、`ConversationPanel.tsx`（触发派生、焦点、IME、键盘、关闭抑制、提交保护）、`assets/main.css`（`.action-picker*` 样式 + 输入行 `position: relative`）、中英文 `conversation.json` 的 `actionPicker` 资源。
- 关闭抑制模型：`none / soft / latched` 三态。`Escape`、`Tab` 设为 `soft`（同一草稿普通重渲染不重开；用户编辑或重新聚焦可重开）；选择行动设为 `latched`（草稿保持 `/` 前缀期间不重开，失去前缀后解除）；失焦仅关闭不设抑制，重新聚焦即按条件重开；锁定通过 `!composerLocked` 参与打开条件（真实窗口中禁用输入框必然失焦）。
