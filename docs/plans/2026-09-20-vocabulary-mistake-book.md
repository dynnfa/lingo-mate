# 词汇练习错题收集与错题集实施计划

- 日期：2026-09-20
- 状态：已实施

## 目标与范围

1. 用户在词汇练习中提交释义并完成审查后，自动收集答错的单词及本次输入的释义。
2. 新增独立菜单“错题集（单词）”，展示已收集的错误单词，重启应用后仍可查看。

本次仅编写计划，不实现功能、不执行数据库迁移或修改用户持久化数据。首版仅覆盖现有“看单词写释义”练习，不包含短语、句子、错题专项练习、删除错题或掌握状态。

## 当前代码基线

- `src/core/learning/vocabulary-practice/vocabulary-practice-service.ts`：管理内存练习会话、词条快照、答案校验、审查和取消；目前不保存练习结果。
- `src/shared/vocabulary-practice.ts`：定义练习协议，审查成功结果包含 `verdict` 和错误标记 `marks`。
- `src/main/vocabulary-practice-ipc.ts`、`src/preload/`：现有练习调用与跨进程安全边界。
- `src/renderer/src/practice/vocabulary/`：练习界面、状态 hook 与错误反馈。
- `src/renderer/src/App.tsx`、`src/renderer/src/hooks/useAppViewNavigation.ts`：菜单入口与页面切换。
- `src/database/migrations.ts`：集中管理 SQLite 迁移；新增迁移版本以实施时最新版本为准。

## 产品行为

### 错题收集

- 仅以完整、校验通过的审查结果中的 `marks` 确定错误项，按 `entryId` 与本次提交答案、Core 中的词条快照关联。不能从总结文字推测错词，也不接受 Renderer 自报的错误结论。
- 每个错误项保存单词快照、本次提交释义和发生时间。释义采用现有提交规则去除首尾空白，不改写用户答案。
- 正确项不收集；全部正确不新增记录。输入不合法、模型失败、超时、取消及被新练习替换的未完成审查不新增记录。
- 校验错误标记属于当前练习、同一词条不重复；`has_errors` 却无错误标记等不一致结果作为无效审查处理，不静默遗漏错题。
- 同一单词多次答错，保留每次提交释义；列表按词条聚合展示一行，显示最近错误释义、累计错误次数及最近错误时间，可展开查看历史错误释义。后来答对不自动清除历史。
- 收集以实际提交审查为单位；同一次提交的重复 IPC 请求或保存重试不重复计数，用户修改答案后再次主动提交属于新一次审查。
- 审查成功后先完成整批错题事务写入，再返回成功。写入失败返回 `STORAGE_FAILED`，保留当前答案并允许重试；不能提示已收集。提交前检查取消状态，事务提交后取消不撤销已保存结果。

### 错题集页面

- 在现有侧边菜单新增“错题集（单词）”，与“练习”“已记录”同级。
- 列表显示单词、最近一次错误释义、错误次数、最近错误时间；按最近错误时间倒序，使用稳定 ID 作为同时间排序条件，支持分页加载。
- 展开某个单词可分页查看错误释义历史，避免将全部历史一次传入 Renderer。
- 覆盖加载、空列表、加载失败、重试及加载更多状态；进入页面时重新读取数据，练习新产生的错题在下次进入时可见。
- 沿用现有返回对话及焦点恢复交互，不丢失对话草稿；较长释义换行展示，时间按当前界面语言格式化。
- 中文菜单名为“错题集（单词）”；英文及全部静态文本、错误提示和无障碍标签同步纳入现有 i18n 资源。

## 数据与边界设计

### 持久化

新增 `vocabulary_practice_mistakes` 表，建议字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 错误记录 UUID |
| `review_id` | 一次提交审查的稳定标识 |
| `entry_id` | 原词条 ID，用于列表聚合 |
| `term` | 练习开始时的单词快照 |
| `submitted_meaning` | 本次输入的释义 |
| `created_at` | 本次错误记录时间 |

- 对 `(review_id, entry_id)` 建立唯一约束，同一次提交中的所有错题在一个事务内写入。
- 为词条历史查询及最近错误排序配置索引。聚合查询和分页在仓储完成，不在 React 中加载全表后处理。
- 快照独立于词库保存，不设置删除词条时级联删除错题；源词删除后仍可查看原错误记录。删除后重新收藏生成新 ID 时视为新词条。
- 不回填上线前的练习：现有结果仅在内存，无法可靠恢复历史错误释义。
- 根据项目约定，实施数据库迁移及持久化数据变更前必须先询问用户；本计划不构成执行这些操作的授权。迁移验证使用临时数据库，保留已有词库和其他业务数据。

### 分层职责

- **Core**：在词汇练习服务中注入错题仓储接口，负责错误项关联、提交身份、取消检查和保存时机；新增错题查询服务，提供聚合列表与历史查询。
- **Database**：新增 `sqlite-vocabulary-mistake-repository.ts`，实现批量事务保存、唯一约束及分页查询。
- **Shared**：新增 `vocabulary-mistakes.ts`，集中定义列表/历史查询的 Zod schema、DTO、错误码和 IPC channel；为练习提交增加明确的幂等语义。
- **Main**：装配仓储与服务，注册可信来源校验后的查询 handler，将存储错误转换为安全错误码。
- **Preload**：新增明确命名的 `window.api.vocabularyMistakes.list` 和 `listHistory`，同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 与共享 API 类型。
- **Renderer**：新增 `mistakes/MistakesPage.tsx` 外层页面，单词菜单组件、`useVocabularyMistakes.ts` 及辅助逻辑放在 `mistakes/vocabulary/`；测试放对应 `__tests__/`。更新导航类型、入口、焦点引用和中英文资源。

本需求明确要求向用户显示错题及输入释义，因此查询接口仅返回该页面必要的展示字段；不扩展为读取任意用户数据、学习记忆或数据库的通用接口。用户输入和模型原始响应不得写入控制台，诊断日志继续遵循项目现有规则。

复用现有审查 Prompt，不新增模型调用；如为收紧审查结果约束而修改 Prompt，继续显式指定解释语言，保持协议字段名和枚举值稳定。

## 实施步骤

1. 确认持久化变更后，确定迁移、错题 DTO、分页协议和提交幂等规则。复用或扩展当前 `requestId` 前先验证其生命周期，确保同次重试复用 ID、主动新提交生成新 ID；同 ID 携带不同答案应拒绝。
2. 按 TDD 实现仓储：先验证批量原子写入、重复提交不重复、历史保留及分页行为，再实现迁移与 SQLite 仓储。
3. 按 TDD 接入练习服务：审查结束校验并保存错误项，覆盖取消竞争和保存失败。保存失败重试复用已完成审查结果，避免再次调用模型产生不同结论；缓存仅保留在当前内存会话，并随会话销毁清理。
4. 实现查询服务、Main handler 和 preload 窄 API，补充来源校验、参数校验及错误映射测试。
5. 实现菜单、列表、历史展开及页面状态，接入中英文翻译，补充组件和导航交互测试。
6. 完成集成与 Electron 端到端验证；全部计划工作及验证完成后，将本文件状态更新为“已实施”。

## 验证与验收

- **核心行为**：提交三词、两词答错，仅保存两词与各自输入释义；全对不写入；重复错误标记、非法词条 ID 和矛盾结果被拒绝。
- **生命周期**：失败、超时、取消、切换新一轮后迟到的模型结果均不落库；写入失败整批回滚，重试不重复计数且不重新审查。
- **数据行为**：同词再次答错，列表仍为一行且次数增加，历史保留两次释义；后来答对不删除；删除原词条不丢失快照；重启后可读取。
- **边界与分页**：重复请求幂等、同 ID 不同答案拒绝、非可信 IPC 来源拒绝、非法游标/条数拒绝；同时间记录分页不重复、不遗漏。
- **界面**：菜单可进入、返回后焦点恢复、加载与空态正确、查询失败可重试、历史展开正确、长释义可读、中英文文案完整。
- **端到端**：使用可控模型替身完成“练习答错 → 查看错题及输入释义 → 重启 → 仍可查看”，不依赖真实模型输出。

测试遵循项目目录规范；新增核心逻辑、状态流转与 IPC 校验均先写失败测试再实现。完成实现后运行相关测试及 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:electron`。
