# 按天归档公共错误日志计划

- 日期：2026-09-18
- 状态：待实施

## 目标

1. 建立 `logs` 文件夹，集中保存应用运行中的错误日志。
2. 按本地日期生成 `YYYY-MM-DD.log`，当天各模块可获取的报错统一追加到同一个公共文件。
3. 保留排查问题需要的原始原因，同时对密钥脱敏，维持现有进程隔离和安全错误返回机制。

本次交付为实施计划，不创建运行时日志目录、不修改业务代码或已有持久化数据。

## 当前情况

- `src/main/ai-import-failure-log.ts` 将 AI 导入失败写入 `app.getPath('logs')` 下的 `ai-import-errors.log`，达到 5 MiB 后保留一份轮转备份；已有部分敏感字段和 API Key 脱敏。
- `src/main/index.ts` 使用 `electron-log/main` 记录词汇导入提交错误，语言偏好初始化失败则使用 `console.error`。

- `src/main/ipc-guard.ts` 统一捕获和转换 IPC 错误，但还需要将原始异常和校验失败接入公共日志。业务内部已经捕获的失败、流式失败不能只依赖此入口收集。
- 实施前应重新扫描全部源码中的 catch、错误结果、诊断回调及 console/electron-log 调用，建立接入清单，逐项核对，避免遗漏或重复记录。

## 设计

### 1. 日志目录与每日文件

默认使用 `join(app.getPath('userData'), 'logs')`，由 Main 在启动早期创建。使用应用数据目录保证开发与安装后的应用均有稳定、可写的位置，不依赖当前工作目录或安装目录。

```text
<userData>/logs/
├── 2026-09-18.log
├── 2026-09-19.log
└── 2026-09-20.log
```

- 每次记录按事件发生时的系统本地日期选择文件；跨午夜无需重启即可写入新文件。
- 时间戳保留时区信息；文件日期和记录日期使用相同时间口径。
- 同一天重启继续追加，不清空旧内容；没有错误的日期允许没有文件。
- Main 是唯一文件写入方，统一串行追加，避免并发请求产生行交错；正常退出时等待队列完成，并设置有界等待。
- 本期不按大小拆分同一天的文件，不自动删除历史日志。后续如需保留期限或容量限制，单独确定策略。
- 原有日志文件保持原样，不搬迁、覆盖或删除；新错误切换到公共日志后停止旧写入路径。

### 2. 公共日志服务

新增 `src/main/error-logger.ts`，集中负责目录创建、日期路由、错误序列化、脱敏和追加写入。由 `src/main/index.ts` 创建实例并注入依赖方；Core 只依赖无 Electron/文件系统依赖的诊断接口，不反向导入 Main。

采用每行一个 JSON 对象的格式，便于检索、多行堆栈转义和后续分析。建议字段：

| 字段 | 内容 |
| --- | --- |
| `timestamp` | 带时区的事件时间 |
| `level` | `error` 或 `warn` |
| `source` | `main`、`core`、`preload`、`renderer` |
| `module` / `operation` | 发生错误的模块和操作 |
| `code` | 已有稳定错误码，无则省略 |
| `message` | 脱敏后的错误描述 |
| `error` | 可获取的 name、stack、cause 链和聚合错误 |
| `context` | 与此次失败相关、经过筛选和脱敏的诊断信息 |
| `requestId` | 已有请求标识，用于关联一次操作；无则省略 |

支持 `Error`、非 Error 抛出值、循环引用和嵌套 cause；限制深度与单条体积，截断必须明确标记。不得直接序列化整个 SDK 错误、配置对象或 IPC 请求。

日志服务自身失败不能覆盖原业务异常或递归记录自身。写入失败时仅向控制台输出固定、不含原始数据的诊断码，限制重复输出；不能把原始日志作为 console 回退。致命异常走尽力同步写入路径，并保留正常终止语义，不因捕获异常而继续运行不可靠状态。

### 3. 错误采集范围

| 来源 | 接入位置与内容 |
| --- | --- |
| Main 启动和生命周期 | 数据库、配置、语言偏好初始化及窗口创建/加载失败 |
| IPC 公共守卫 | handler 异常、错误映射异常、输入/返回结果校验失败；拒绝请求只记录安全元信息 |
| 业务与数据库调用 | 已捕获并转换为失败结果的错误、持久化失败、导入导出失败及文件读写失败 |
| LLM 与学习流程 | 网络/模型请求失败、响应解析失败、AI 导入失败、近义词诊断及用量记录失败 |
| 流式任务 | 在错误转换或失败事件发出前记录原始原因，保持完成、失败、取消终态 |
| Preload | 会话事件解析等现有可捕获的桥接错误 |
| Renderer | 全局 error、unhandledrejection、React 错误边界及已捕获但未上报的 UI 异常 |
| 进程级事件 | Main 未捕获异常和未处理拒绝、Renderer/子进程异常退出等可获得的原因 |

主动取消不计为错误；输入校验拒绝、资源不存在等预期失败可记录为 warn，仅保留错误码与安全上下文。已在源头记录的错误不因逐层转换而重复写入，优先通过现有 requestId 和明确的记录责任边界关联。

进程被强制终止、操作系统崩溃或磁盘不可写时，无法保证取得堆栈或成功落盘；不承诺恢复运行时未曾获取的错误信息。

### 4. 跨进程边界与脱敏

- Preload/Renderer 通过明确类型的 `window.api.reportError` 上报受限诊断结构；同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 和 shared 中的协议/schema/channel。
- 新 IPC 入口复用可信来源校验，限制字段、长度、频率和载荷体积。禁止任意路径、任意 channel、文件写入或读取日志接口；上报失败不再触发上报，避免循环。
- Main 生成可信时间和来源元信息，不信任 Renderer 提供的文件名、路径或进程身份。
- 统一脱敏覆盖敏感字段、Authorization/Bearer、URL 中的凭据及文本/stack/cause 中已知 API Key。模型配置变更后仍须覆盖在途请求使用的密钥；测试涵盖嵌套对象和自由文本。
- 仅在失败诊断需要时保存相关用户输入和模型原始响应；这些内容只写 Main 管理的本地日志，不转发给 Renderer 或控制台，不扩大为成功请求日志。
- 新建文件使用仅当前用户可读写的权限（平台支持时），目录限制访问权限。不新增面向用户的日志查看页面；若实施中新增提示，必须使用现有 i18n 资源。

## 验收标准

1. 启动后存在 `<userData>/logs`，不同模块当天的错误均追加到同一个 `YYYY-MM-DD.log`。
2. 跨天自动切换，同日重启不覆盖，连续并发错误的每一行均为可解析 JSON。
3. 当前错误入口清单全部接入或明确记录无法采集的原因；旧 AI 导入日志及默认 electron-log 文件不再接收新的重复错误。
4. 原始异常的 message、stack、cause 及必要的模型失败响应可在本地日志定位；截断有标记。
5. 模拟密钥在字段、自由文本、URL、堆栈和模型响应中均被脱敏；日志内容不回传 Renderer 或 console。
6. 日志写入失败不改变业务结果或导致流式任务永久生成；主动取消不生成 error 记录。
7. 不可信来源、超大载荷和上报循环受到限制；Renderer 仍无 Node.js/Electron/文件系统直接访问能力。

## 验证方式

本次只新增文档，通过内容和 diff 检查验证，不要求运行代码测试。实施时按行为逐项先写失败测试，再实现通过：

- 单元测试放在相应模块的 `__tests__/`，日志写入使用临时目录与可控时钟，不访问用户真实数据。
- 跨模块测试放在 `tests/integration/`，验证不同来源共用文件和异常转换前保留原因。
- Electron 测试放在 `tests/e2e/`，使用隔离的 userData，验证启动建目录、Renderer 上报和本地落盘。

