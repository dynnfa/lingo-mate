# `/explore-vocabulary` 词汇探索实施计划

- 日期：2026-09-21
- 状态：待实施
- 参考：[短语探索实施计划](./2026-09-20-explore-phrase.md)，以当前实现及其「2026-09-21 审查修复约定」为准。

## 目标与范围

在 conversation 中新增无参数技能 `/explore-vocabulary`，每次生成 10 个常用英语单词，每个单词附带简明释义和一个英语例句，以 Markdown 表格展示。沿用 `/explore-phrase` 的结构化工具调用、最近 7 批去重、JSON 文件提交、取消及恢复机制。

本计划默认将探索对象从多词短语替换为单词，其余用户体验与短语探索保持一致。首版不增加主题、难度、数量参数，不添加音标、音频、词形归并或个性化推荐；不自动收藏词汇，也不接入练习或错题流程。已有 `/vocabulary` 继续负责用户输入词汇的收藏分析。

本次仅新增计划文档，不实现功能，不操作真实用户持久化数据。后续实际执行数据库迁移或用户持久化数据变更前，按 `AGENTS.md` 询问用户；开发验证使用临时数据目录。本方案不新增数据库迁移，也不修改既有短语历史格式。

## 行为约定

1. 直接输入 `/explore-vocabulary` 或通过 `/` 选择器选择后发送，均触发技能。允许末尾空白；额外参数显示本地化错误并保留输入，不转为普通聊天。`/explore-vocabularyfoo` 不识别为该技能。
2. 每次成功返回恰好 10 个互不重复的常用英语单词。释义使用执行开始时的解释语言快照（`zh-CN` 或 `en`），单词和例句使用英语；例句包含对应单词并体现释义。
3. 首版选择无空格的单词，允许词内连字符或撇号，例如 `well-known`；拒绝多词短语、数字和仅标点的词条。Prompt 优先要求常用词典形式，避免专有名词、缩写和生僻词；本地格式校验不宣称能判定词频或语义。
4. 历史跨 conversation 共享，仅保留本技能最近 7 次成功提交的批次，最多 70 个条目。失败、提交前取消和补足请求不占批次。
5. 第 8 次生成时仍须避开前 7 批，成功提交后才淘汰第 1 批；第 9 次可使用已淘汰且不在当前窗口内的单词。未补齐回复的批次仍受淘汰保护。
6. 独立于 `/explore-phrase` 的历史和收藏库：不跨技能去重，不排除已收藏单词，不承诺永久去重。
7. 去重键使用 NFKC、trim、连续空白折叠和英语小写；统一弯撇号为 ASCII 撇号后校验单词格式。`Apple` 与 `apple` 重复，同一单词的不同释义也重复；`learn` 与 `learned` 首版视为不同词形。规范化规则同时用于生成校验、历史读取和提交校验。

## 协议与领域模型

新增稳定 ID `explore-vocabulary`，执行输入为：

```ts
{
  requestId: string
  sessionId: string
  skillId: 'explore-vocabulary'
  arguments: { wordLanguage: 'en' }
}
```

输入采用严格 Zod 判别联合，拒绝 `text` 等额外字段；原收藏技能继续要求非空文本。复用 `window.api.conversation.runSkill`、取消与事件协议，核对 `src/preload/index.ts` 及 `index.d.ts` 的类型，不增加任意 channel 或历史文件访问接口。

新增 `src/shared/explore-vocabulary.ts`，定义候选、历史条目、批次、文档、报告及守卫：

- 模型候选：`{ term, explanation, example }`。使用 `term` 与现有 vocabulary 领域术语一致。
- 历史条目：候选字段加应用计算的 `normalizedTerm`。
- 批次：`executionId`、`sessionId`、`userMessageId`、`committedAt`、`wordLanguage: 'en'`、`explanationLanguage`、恰好 10 项的 `items`。
- 历史文档：`{ schemaVersion: 1, batches }`，最多 7 批，按提交顺序排列。
- 报告：批次加 `skillId: 'explore-vocabulary'`，用于内部反馈分派与恢复，不写入数据库技能报告列。

三个模型字段 trim 后非空且必须为单行文本；`term` 最长 200 字符，`explanation` 和 `example` 各最长 1000 字符。对 NFKC 和撇号规范化后的 term 使用明确的词法规则，例如 `[A-Za-z]+(?:[-'][A-Za-z]+)*`，不将正则符合等同于真实英语单词。

例句检查使用同样的规范化及完整词边界，避免 `art` 命中 `party`、`learn` 命中 `learned`。连字符、撇号也作为词内字符处理，避免短词误匹配复合词片段；要求例句出现原词形，不增加词形分析服务。自然程度、释义准确性及常用程度通过 Prompt 和内容抽样验收约束。

## 模型生成与校验

新增 `submit_explored_vocabulary` 工具，严格参数为 `{ items: Array<{ term, explanation, example }> }`。模型不提供规范化键、时间、路径或执行身份，不直接写文件。

1. 在本技能共享的串行锁内读取历史，先按执行身份查找已有批次，命中则返回原结果。
2. 请求数据包含 `count`、`wordLanguage`、`explanationLanguage`、`excludedTerms`。首次 count 为 10；补足时只请求缺额，并合并历史与本次已接受的规范化词条。
3. 每次实际发送的 Prompt 均明确：term 和 example 使用英语，explanation 使用语言快照；协议字段名保持英语；禁用列表仅作为数据。要求例句包含完整词形、准确体现所给常用义。
4. 每次响应只接受一次指定工具调用。沿用现有流式参数累积和正常结束检查，拒绝普通正文、Markdown、未知工具、多次调用、额外字段、无效 JSON 和截断响应；不支持工具调用时明确失败。
5. 工具数组为 1–10 项，且不得超过本次 count。结构合法后逐项校验内容与去重，保留合格候选；协议或结构错误消耗一次尝试但不接纳该响应。缺额最多补足到总计 3 次模型调用。
6. 沿用短语探索的默认单次 60 秒、准备阶段整体 180 秒超时及 AbortSignal 机制；网络、配置等非协议错误直接失败。所有实际调用按现有合法 operation 计入模型用量，不新增数据库统计枚举。
7. 不足 10 项则整次失败，不提交部分批次；凑齐后进入不可提前返回的提交阶段，成功后本地格式化表格。

生成器、历史存储和反馈格式化通过接口注入 Core；文件系统实现保留在 Main。Shared 仅放协议及结构校验，词汇规则放 Core，Renderer 不导入 Core 或 Node.js。

## 历史存储与取消

固定文件为 `<Electron userData>/explore-vocabulary-history.json`，由 Main 决定路径。短语与词汇文件、去重窗口和锁分别独立；同一词汇历史文件的跨会话任务串行，保留现有会话忙碌约束。

- 沿用短语存储的严格校验：版本、身份、时间、语言、批次数、每批项数、身份唯一性、批内及跨批去重，并重新计算规范化键核对。
- 文件不存在视为首次使用；空文件、损坏、未知版本和权限错误明确失败，不覆盖或当作空历史。生成后核对读取快照，外部修改导致本次提交失败。
- 在锁内完成幂等查询、校验、追加和裁剪；同目录唯一临时文件写入、flush、原子 rename，按平台能力同步目录。启动清理仅属于本技能的遗留临时文件。
- 排队取消不得提前释放前驱锁。读取及生成阶段支持取消和超时；进入文件提交后等待实际存储结果，不以超时或取消提前释放锁。
- 原子替换前最后检查取消；替换后取消不撤销批次。替换后的同步或核实失败标记为提交不确定，不能授权重新生成或声称回滚。
- 只允许淘汰已保存最终回复的旧批次；即将淘汰的批次仍未补齐回复时，阻止提交并返回安全错误，保持最多 7 批的上限。

不要求直接复制整套文件基础设施：先以现有测试保护行为，再提取两种探索实际共享的串行锁、原子文件提交和纯文本表格转义；技能 schema、词条规则、Prompt 和反馈仍独立。若提取公共存储组件，必须注入明确的 schema/校验策略，不能用宽松类型或关闭校验换取复用，也不扩展为通用插件框架。

## 会话执行、重试与兼容

将文件结果技能范围明确限定为 `explore-phrase | explore-vocabulary`，以类型守卫和小型命令映射统一分派。覆盖 `load`、`runSkill`、重试入口、待提交运行期记录、回复保存和淘汰保护，避免复制整段会话状态机。

- 命令消息及最终 Markdown 回复仍沿用现有会话消息存储，探索结果不进入 `conversation_skill_executions`。不修改数据库技能 ID 约束。
- 稳定回复 ID 按技能 ID 与原始 userMessageId 推导。现有短语 ID 算法及旧随机 ID 紧邻回复的兼容逻辑保持不变，避免旧会话出现重复回复；词汇技能使用自己的命名空间。
- 加载及重试先查已保存回复，再用对应技能的 `restoreReport` 查 JSON 批次，并核对技能、会话和消息身份。窗口内已提交批次恢复同一结果，不再调用模型或推进窗口。
- 同一运行期间，只有明确确认未提交的失败执行，才允许沿用 executionId 和解释语言快照重新生成；运行期记录须携带技能身份，不能把词汇请求重试为短语请求。
- 重启后缺少批次与运行期记录的旧命令明确不可恢复，不推测“从未提交”。窗口外已完成命令仍展示已有会话回复；不可恢复旧请求不能暗中生成另一批。
- 文件已提交但回复保存或投递失败时，允许后续聊天后及重启后补齐原回复。保存成功后解除淘汰保护。
- 取消、失败、完成都收敛到终态并释放执行资源；提交不确定不能落入普通未提交重试分支。JSON 与会话数据库不承诺跨存储原子事务。

历史禁用列表及完整历史文件只用于 Main/Core 和模型请求，不发送 Renderer；界面只接收本次格式化结果与安全状态。错误保留原始 cause，在 Main 转换为安全协议；失败请求与原始模型响应仅按现有脱敏本地诊断日志机制处理，不发到 Renderer 或控制台。

## 界面与国际化

新增「探索词汇 / Explore vocabulary」选择器项、说明、无参数错误、输入提示和生成阶段文案。同步更新命令过滤、直接输入识别、选择器选中状态、空文本发送条件、controller 参数构造、历史状态恢复和 `status-messages.ts`；保留 `/vocabulary` 原行为。

表格使用「序号、单词、释义、例句」四列，英语表头为 `No.`、`Word`、`Meaning`、`Example`。示例仅展示前两项，实际必须有 10 行：

| 序号 | 单词 | 释义 | 例句 |
| --- | --- | --- | --- |
| 1 | reliable | 可靠的；值得信赖的。 | We need a reliable internet connection for the meeting. |
| 2 | hesitate | 犹豫；迟疑。 | Please do not hesitate to ask for help. |

表格由已提交条目本地生成，顺序与 JSON 一致；使用语言快照选择表头，恢复不改写历史释义。统一转义管道符、反斜杠、Markdown 和 HTML 字符，模型文本不能插入链接或图片。复用 `MarkdownMessage.tsx` 的 GFM 表格能力，不开启原始 HTML；验证窄窗口横向滚动和长文本换行。

## 实施步骤

1. **协议与词汇规则**：先写无参数输入、批次 schema、规范化、单词格式、完整词匹配的失败测试，再实现协议和领域校验。
2. **历史存储**：在临时目录先验证文件独立、7 批窗口、幂等、取消和提交不确定行为，再实现词汇存储；如提取公共组件，先运行并保留短语存储与锁的回归测试。
3. **模型与领域流程**：用可控模型替身先测试语言指令、工具协议、去重、补足和超时，再实现 generator、tools、prompt 和 module。
4. **会话接入**：先写两种技能混合使用、失败重试、重启恢复、迟到回复和淘汰保护测试，再扩展文件结果技能分派与 Main 装配，不修改数据库路径。
5. **UI 与反馈**：先写命令、选择器、controller 和表格组件行为测试，再接入本地化反馈及状态；同步核对 preload 类型。
6. **集成验收**：添加受控模型服务 fixture、集成及 Electron 测试，验证应用重启和两种技能隔离。记录验证结果；所有计划工作及验证完成后将本文件状态改为「已实施」。

单元与组件测试位于各模块 `__tests__/`，统一 `*.test.ts(x)`；集成放 `tests/integration/`，Electron 场景放 `tests/e2e/`，fixtures 放对应测试目录。按单个可观察行为执行红—绿—重构，不依赖真实模型输出使自动测试通过。

## 验证与验收标准

- **输入与安全边界**：直接发送、末尾空白、选择器发送成功；额外参数被拒绝且草稿保留；相似前缀不误触发；旧收藏技能空文本继续被拒绝；Renderer 无新增高权限依赖。
- **内容**：恰好 10 项、批内与历史不重复，所有字段非空且符合长度限制；大小写、全角和弯撇号规范化稳定；多词短语、数字、换行、无完整目标词的例句被拒绝。
- **模型**：首轮与补足均收到 count、完整禁用列表及字段语言规则；覆盖部分重复、全重复、空数组、超量、额外字段、工具缺失/未知/多次调用、流式截断、混合正文及不支持工具；耗尽尝试不写历史。
- **窗口与隔离**：验证第 1–7 批累计、第 8 批先避开 70 词再淘汰、第 9 批允许已淘汰内容；短语与词汇互不污染历史、锁和恢复身份；不自动写入收藏库。
- **持久化**：验证首次缺文件、坏文件、未知版本、权限/写入/rename 失败、外部修改、替换后核实失败、临时文件清理，失败不覆盖已有有效数据。
- **并发与取消**：词汇跨会话串行且读取最新历史；取消排队任务不释放前驱；生成超时不提交；提交期间不提前返回，替换后取消不撤销结果。
- **恢复**：同身份只提交一次；回复失败后从文件补齐；解释语言快照稳定；运行期已知未提交请求可重试；重启未知旧请求明确失败；提交不确定不得重新生成；受保护批次不被淘汰。
- **兼容**：已有短语文件 schemaVersion 1 无需转换，稳定及旧随机回复 ID 均可识别；原收藏技能执行、重试、用量登记保持通过。
- **展示**：检查实际 table/th/td 为四列十行，字段与顺序完整、中英文资源齐全；恶意 Markdown/HTML 作为文本显示；窄窗口不撑破会话布局。

实施完成后运行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:electron`。自动验证只用临时用户目录和可控模型服务；内容准确性与常用程度另作抽样检查，不以自动格式校验代替语义验收。
