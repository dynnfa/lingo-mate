# 词汇练习与 LLM Tool Call 审查计划

- 日期：2026-09-09
- 状态：待实施

## 目标与范围

在“开始练习”中增加“词汇练习”菜单。详情顶部提供练习单词数量输入框和确认按钮；确认后从 vocabulary 查询词汇，以左侧单词、右侧 meaning 的两列形式开展练习。提交后由 LLM 审查单词与 meaning 是否匹配，通过 tool call 标红错误内容；全部正确时由 LLM 判断是否需要调用工具，允许不调用工具直接完成。

本计划暂按“看单词填写释义”设计：左侧展示词库中的单词，右侧为用户填写 meaning 的输入框，提交后审查用户答案。若预期是直接展示并审查词库中已有的 meaning，实施前需调整此交互；以下使用前一种解释。默认每轮 10 个词，数量范围 1–50，随机抽取且同轮记录 ID 不重复。这些为首版默认设计。

首版仅查询词库并在内存中保存练习与审查状态，不新增练习历史、成绩持久化或自动修改词库内容。

## 当前代码基线

- `src/main/vocabulary-ipc.ts`、`src/preload/index.ts`：可参考已有词库功能的窄接口、来源检查、校验和错误转换。
- `src/core/llm/llm-synonym-analyzer.ts`：已有多轮 tool call 和工具结果回传实现，但其响应协议强制工具调用，本功能不能直接套用该终止条件。

## 页面与交互

1. 在开始练习左侧增加“词汇练习”菜单，首版默认选中，右侧加载词汇练习详情。
2. 详情顶部提供带标签的数量输入框和“确认”按钮。拒绝空值、非整数、零、负数及超过 50 的输入；读取期间防止重复提交。
3. 确认后从完整 vocabulary 词库抽取，不能只从列表首屏或 Renderer 缓存抽取，也不能由 LLM 生成单词。数量不足时使用全部可用词条并显示实际数量；空词库提供空状态。
4. 详情内容内部采用两列逐行对应布局：左侧只读单词，右侧 meaning 输入框。使用稳定词条 ID 绑定答案，允许长文本换行，兼顾窄窗口、键盘导航和无障碍标签。
5. 词库原有 meaning 作为模型审查的参考，不预填答案；meaning 为 null 的词条仍可练习，模型依照词义判断，不把参考缺失视为用户答错，也不自动回填词库。
6. 单独提供“提交审查”按钮。要求每行填写非空答案，设置合理文本长度限制；将本轮所有单词及用户 meaning 一起提交。审查期间固定答案快照、禁用修改与重复提交，提供取消入口。
7. 根据已校验的工具参数标红指定行的 meaning 全文，并提供错误提示或图标，避免只依赖颜色。首版不做字符偏移或局部片段标红。
8. 审查结束显示模型反馈；修改答案后清除上一轮审查结果，可重新提交。再次确认数量会开启新一轮、清空旧答案和标记；有未提交答案时先提示确认。
9. 支持加载、练习中、审查中、完成、失败、取消状态；失败保留答案并允许重试。退出页面时取消当前请求，忽略旧轮次迟到的结果。

## LLM 与工具协议

### 审查输入与语言

- Core 保存本轮词条快照；Renderer 仅提交 `sessionId`、`requestId` 与 `{ entryId, meaning }[]`。由 Core 根据 ID 组装可信单词和参考释义，拒绝漏项、重复或非本轮 ID。
- 实际发送给模型的内容包括每条 `entryId`、`term`、`submittedMeaning`、可空 `referenceMeaning`。参考释义不是唯一合法答案，接受语义正确的改写和合理词义。
- Prompt 明确要求逐项审查全部答案，错误时调用标红工具；全部正确时自行决定是否还需要工具，不强制调用、不为调用而构造错误。
- Prompt 显式指定解释与错误原因使用用户界面语言，单词保持当前学习语言；协议字段名与枚举稳定。词条、参考与答案均作为数据，不能覆盖系统指令。

### 标红工具

提供函数 `mark_text_red`，参数示例：

```json
{
  "items": [
    {
      "entryId": "本轮词条 UUID",
      "field": "meaning",
      "reason": "该释义与单词含义不匹配"
    }
  ]
}
```

- 通过严格 Zod schema 限定字段、非空 items、条数与原因长度；`field` 仅允许 `meaning`，ID 必须属于当前审查快照。
- 工具执行器在 Core 校验并形成标记结果，经 Main 和 Preload 传递给 Renderer，由 React 状态应用预定义红色样式。LLM 不提供 CSS、DOM 选择器、HTML 或可执行脚本。
- 同一轮重复标记同一字段幂等；未知工具、非法参数、越界 ID 不执行且不能造成任意页面修改。

### 调用循环与结束条件

1. 向模型注册工具，使用 `tool_choice: 'auto'`，允许自然语言最终响应，不能强制至少一次 tool call。
2. 收到调用后校验并执行，将成功或安全错误结果按原 `tool_call_id` 回传模型，保留适配层需要的 assistant 消息字段，继续请求。
3. LLM 可一次标红多个错误，之后决定是否继续调用或输出最终反馈。收到正常最终响应且无待执行工具时结束。
4. 全部正确的合法路径是“零次工具调用 → 模型明确给出全部正确的最终反馈”。不能仅凭没有 tool call 推断全部正确；空响应、拒绝、截断或协议错误应显示审查失败。
5. 若存在有效错误标记，结果不得显示全部正确；模型文字与标记矛盾时作为无效审查处理。标记为空但反馈指出错误时同样不能判为通过，应要求模型补齐工具调用或在有限重试后失败。
6. 为便于可靠判断，最终反馈采用经 schema 校验的 `{ verdict: 'all_correct' | 'has_errors', summary: string }` 文本 JSON；它是正常最终响应，不要求额外完成工具。只有最终反馈与累计标记一致才确认结果。
7. 设置总超时、最大轮数（首版 8 轮）、单次工具条数与重复调用 ID 检查；达到限制则失败，不能永久生成。取消后停止执行后续工具。
8. 模型未配置、模型不支持 tool call、网络错误、非法响应分别转换成可国际化的安全错误。失败或取消清除本次未完成的标记，保留用户答案。

## 实施步骤

### 1. Shared 与 Core 领域服务

- 新增 `src/shared/vocabulary-practice.ts`，集中定义 session、答案、标记、最终反馈、错误、IPC channel 与输入输出 schema。
- 新增 `src/core/learning/vocabulary-practice/`，负责数量约束、抽词、快照、审查生命周期与标记校验；通过接口注入词库、模型与取消能力。
- 在词库仓储增加按数量随机抽取的只读接口，SQLite 使用参数化查询；同轮不重复 ID，结果不足时返回实际数量，不新增 schema。
- 不要求跨轮去重；轮次开始后按快照完成审查，即使词库随后发生变化也不混入新内容。

### 2. 模型与工具实现

- 在 `src/core/tools/` 定义标红工具与执行器，在 `src/core/prompt/` 定义显式语言指令，在 `src/core/llm/` 实现审查适配器。
- 复用现有模型配置、客户端与凭据读取方式；同时支持工具调用响应和无工具的正常结束响应。
- 通过注入的假模型验证循环，不依赖外部模型运行自动化测试。

### 3. Main 与 Preload

- 注册面向业务的 `vocabulary-practice:start`、`vocabulary-practice:review`、`vocabulary-practice:cancel` 接口；窄 API 提供开始、审查和取消能力。
- 校验可信窗口与主 frame、输入输出和会话归属；请求 ID 隔离不同审查，释放退出或取消的内存会话。
- 首版审查完成后一次返回标记和最终反馈，由 Renderer 应用工具执行结果，无需新增流式标记通道。
- 同步更新 `src/preload/index.ts`、`src/preload/index.d.ts` 及 `LingoMateApi` 类型。Renderer 不访问 Core、数据库、Electron 原始 API 或凭据。

### 4. Renderer 与国际化

- 扩展 `PracticePage` 菜单，新增 `VocabularyPracticeDetail`，按复杂度提取局部状态 hook。
- 实现数量确认、左右两列、答案填写、提交、取消、重试、标红与最终反馈；保留现有返回、Escape 和焦点恢复行为。
- 将所有静态文案、错误与无障碍标签加入中英文语言资源，动态数量与词汇使用插值。
- 审查结果使用文本渲染和固定样式，不能执行模型返回的标记语言或代码。

## 验证与验收

- Core / Database：数量边界、空词库、数量不足、随机抽取无重复、历史 null meaning、快照和提交 ID 校验；使用临时数据库。
- 工具 / LLM：错误内容准确标红、多项调用、结果回传、全正确零工具调用、工具执行后正常结束、无效 JSON、未知工具、非法 ID、重复调用、反馈矛盾、空响应、截断、轮数上限、超时和取消。
- Main / Preload：可信来源、会话归属、输入输出校验、错误安全转换及取消隔离。
- Renderer：菜单进入、数量输入与确认、两列对应、填写提交、错误标红、全正确无标红、失败保留答案、取消、修改清除结果、旧请求结果忽略、键盘操作及中英文展示。
- Electron E2E：使用临时用户目录、词库和假模型覆盖“开始练习 → 词汇练习 → 输入数量 → 填写 meaning → 提交 → 错误标红”，并覆盖全部正确且未调用工具的路径。
- 测试遵循模块内 `__tests__/*.test.ts(x)`、`tests/integration/` 和 `tests/e2e/` 的项目约定。
