# Lingo Mate 功能待确定清单

状态：待讨论，未确定实施范围

创建日期：2026-09-18

代码基线核对：2026-10-21；以下已有能力与缺口按本次核对更新，产品建议仍待讨论。

本文记录从产品角度提出的功能建议，作为后续讨论和取舍的依据，不代表已确认的需求或实施计划。分析基于当前代码、界面文案和规划文档，尚未通过实际界面体验及用户访谈验证。文中的优先级、目标人群和学习流程均为产品假设。

## 一、当前产品判断

项目已经具备“收集词汇 → 理解 → 练习 → AI 点评”的基础。下一步最值得补齐的是：练习结果如何影响之后的学习。

当前实现更接近一个有 AI 辅助的个人英语词库。要兑现“持续、个性化的学习助手”这一定位，需要记住用户的学习表现，并据此安排下一步。

### 已有能力

- 对话、概念讲解、词汇和短语收录、近义词辨析。
- 词汇 Excel 导入导出、AI 批量解析。
- 随机抽词释义练习，以及三词造句、提示和点评。
- 词汇错题持久化、逐词错误次数与错误作答历史查看。
- 自定义模型、语言设置、模型用量统计。

### 建议聚焦的产品价值

把用户实际遇到、想掌握的表达，转化成能反复练习的个人学习材料。

建议优先验证的目标人群：日常在电脑上阅读、写作，有一定英语基础，但经常“看得懂、用不出来”的学习者。这个方向与已有词库和造句能力比较吻合。

待确定：

- 是否以这类学习者作为首批目标用户？
- 第一阶段重点解决词义记忆、书面表达，还是其他具体问题？

## 二、学习闭环：让练习结果影响下一次练习

### 当前缺口

词汇练习和造句练习均使用随机抽样。当前词汇练习已持久化错题、错误次数和错误作答历史；练习会话与完整审查结果仍在内存中，正确作答未形成持久化学习记录，造句练习也没有完整结果历史。逐词长期能力状态、按表现调整选题和到期复习调度尚未实现，因此今天答错一个词仍不会自动改变明天的练习安排。

相关实现：

- [词汇练习服务](../src/core/learning/vocabulary-practice/vocabulary-practice-service.ts)
- [造句练习服务](../src/core/learning/sentence-practice/sentence-practice-service.ts)
- [词汇错题仓储](../src/database/sqlite-vocabulary-mistake-repository.ts)

### 建议补充

| 功能               | 用户价值                                                       |
| ------------------ | -------------------------------------------------------------- |
| 完整练习历史       | 在已有词汇错误作答历史基础上，补充正确作答、造句和完整练习结果 |
| 逐词学习状态       | 区分没练过、记不住、理解了但不会用                             |
| 错题回练与到期复习 | 薄弱内容会再次出现                                             |
| 重新作答           | 看完点评后，有机会独立纠正                                     |
| 延迟检验           | 隔几天确认是否还记得、能否换语境使用                           |

需要区分“认识词义”和“能正确使用”。一次释义答对，不宜直接判定为已掌握；看过提示后答对，也应与独立完成有所区别。

第一版可以采用简单、可解释的复习规则，先验证学习流程，无需立即引入复杂算法。

重复提取练习对延迟记忆的帮助有实验支持，但具体复习规则仍需在产品中验证。参考：[The Critical Importance of Retrieval for Learning](https://doi.org/10.1126/science.1152408)。

待确定：

- 保存哪些练习信息，以及保存多久？
- 如何分别表达词义记忆和实际使用能力？
- 复习的时间、数量和选题规则是什么？
- 用户是否可以调整学习状态、跳过或暂停某个词的复习？

## 三、今日练习：打开后知道做什么

### 当前缺口

当前入口围绕会话、已记录词汇和开始练习展开，用户需要自己决定聊什么、练什么、练多少。

### 建议补充

增加“今日练习”入口，把已有能力串成一个有限、可完成的学习流程。例如：

> 今天约 8 分钟：复习 5 个词，重练 2 个上次用错的表达，完成 1 个情境造句。

以上数量和时长仅为示例，不是确定规则。关键体验包括：

- 有明确的开始按钮。
- 任务量有限，能够完成。
- 中断后能继续。
- 完成后知道本次收获，以及仍然存在的困难。

待确定：

- 今日练习是否作为默认首页？
- 每日任务量由用户设置，还是根据历史表现推荐？
- 新用户没有词库时，如何开始第一轮有效练习？

## 四、真实表达任务：从随机造句走向语境使用

### 当前缺口

三词造句已经提供了输出练习的起点，但随机词汇组合可能产生生硬任务。当前提示也是点评前的必经步骤。

### 建议补充

- **情境任务**：解释延期、表达不同意见、介绍项目等，让词汇服务于表达目的。
- **按需提示**：先尝试独立作答，需要时再查看搭配或例句。
- **短语与近义词练习**：将已有收录内容用于选词、替换表达和语境辨析。
- **分层反馈**：区分语法错误、意思不准确、搭配问题和可选的风格优化。

例如，一个句子已经正确，只是不够正式，反馈应明确说明“可以这样优化”，避免让用户误以为原表达错误。

待确定：

- 优先支持哪些情境和练习形式？
- 是否保留三词随机造句作为独立模式？
- 如何处理用户对 AI 点评的异议？
- 点评后的重新作答与后续复习如何衔接？

## 五、个人词库：降低收录和再次使用的成本

### 当前基础

项目已支持命令和行动选择器，可以在现有入口上补充更直接的操作。

### 建议补充

- 在回答中选中单词或表达，一键收藏。
- 收藏时保留原句、来源和个人备注。
- 在词库中搜索、编辑、按主题筛选。
- 从词条直接开始练习，或追问用法。

原始语境值得优先考虑：用户再次看到一个词时，能够想起它来自哪篇文章、哪次表达需求，让词库成为个人学习资料。

当前“词汇”本身也能收录短语，界面又有单独的“短语”菜单，需要明确分类规则，避免用户纠结存放位置。可以考虑统一收录入口，再按内容类型展示。

待确定：

- 词汇、短语、近义词应如何组织和关联？
- 是否采用统一收录入口？
- 首版需要支持哪些来源信息和筛选维度？
- 用户编辑内容后，如何处理已有练习和学习状态？

## 六、轻量个性化：让偏好实际改变体验

### 当前缺口

目前语言偏好主要包含界面语言和目标语言，尚不足以决定用户适合什么题目和反馈方式。

### 建议补充

- 学习目的：工作表达、阅读、考试或日常交流。
- 自评水平与练习表现。
- 感兴趣的主题。
- 每次可投入的时间。
- 希望被纠正的方式和程度。

这些信息应实际影响题目与反馈。例如，同一个词，对工作场景用户生成邮件练习，对旅行场景用户生成交流任务。

优先验证少量、可修改的信息是否能稳定改善体验，再决定是否扩展长期记忆能力。

待确定：

- 首次使用时必须询问哪些信息，哪些可以以后补充？
- 用户主动设置与练习表现推断发生冲突时如何处理？
- 如何让用户查看、修改或清除这些偏好？

## 七、学习反馈：提供进步的证据

### 当前缺口

模型用量统计能说明调用了多少，但用户更需要知道学习是否有效。

### 建议补充

- 上次不会、这次能独立答对的词。
- 隔一段时间仍能回忆的内容。
- 反复出现的错误类型及其变化。
- 同一表达的首次作答与后续改进。

收藏数量和练习次数可以展示，但不宜直接等同于学习成果。指标应区分有提示与无提示、即时重答与延迟复习。

待确定：

- 哪些信息放在单次练习总结，哪些放在长期学习回顾？
- 如何定义进步，避免将 AI 点评结果包装成精确的能力测量？
- 如何通过真实使用验证这些反馈是否帮助用户持续学习？

## 八、面向外部用户的基础体验

如果后续面向外部用户，应进一步评估：

- 首次使用引导，帮助用户完成第一次收录与练习。
- 模型配置引导，降低配置门槛。
- 覆盖词库之外数据的备份恢复，复用已有词汇导出能力。

待确定：

- 产品优先服务自用场景，还是准备面向其他用户？
- 是否继续以用户自行配置模型为前提？
- 备份范围是否包含会话、学习偏好和未来的练习历史？

## 九、建议优先级

以下为讨论用排序，尚未确定实施。

| 优先级 | 内容                                 | 目的                     |
| ------ | ------------------------------------ | ------------------------ |
| P0     | 练习历史、错题回练、简单复习队列     | 让学习表现影响下一次练习 |
| P0     | 今日练习入口、完成反馈               | 形成清晰的每日使用流程   |
| P1     | 情境练习、按需提示、短语与近义词练习 | 提升实际表达能力         |
| P1     | 词库搜索编辑、原句收藏、轻量学习偏好 | 提升个人材料的使用价值   |
| P2     | 语音、更多语言、多平台接入           | 在核心流程验证后扩展     |

已有[聊天平台接入规划](plans/2026-09-11-chat-platform-integration.md)可以保留。如果用户访谈发现“收藏入口不方便”是最大阻碍，可以提前验证一个最小入口；否则建议优先完成学习闭环。

如果下一版只能选择一个方向，建议是：

> 今天练错的内容会被记住，几天后自动换一种语境再练，并告诉用户这次是否真的进步了。

## 十、确定需求后的下一步

1. 确认首批目标用户和主要学习问题。
2. 从上述建议中选择最小可验证范围。
3. 明确用户流程、验收标准和验证学习效果的方式。
4. 对已确定的范围另行编写实施计划。

涉及练习历史、学习状态等持久化能力时，对真实用户数据库执行迁移或变更持久化用户数据前，需按项目约定先征询用户意见。编写迁移代码和使用可丢弃临时数据库测试本身不要求提前确认，不能因此打开或升级真实用户数据库。本文仅记录候选功能，不构成执行迁移或数据变更的授权。
